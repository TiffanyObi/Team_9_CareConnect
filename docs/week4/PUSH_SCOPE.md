# Week 4 Push Scope

## Appropriate for team review and a future pull request

- Original Week 4 requirement summaries, acceptance criteria, implementation plan, risks, and verification checklist under `docs/week4/`.
- The repeatable `mobile-flutter-app/tool/verify_week4.sh` workflow.
- Automated accessibility tests adapted to the canonical `mobile-flutter-app/`.
- Focused future application changes that extend the current feature/core/app structure and pass review.
- Final README updates and selected current screenshots once the implemented screens are verified.

## Keep local; do not push in this branch

- `Week4 .docx`, `OPENAI Codex Projects.pdf`, Assignment 3 source documents, and other instructor/book materials unless redistribution permission is confirmed.
- Personal Codex workspace files such as `CODEX_TEMPLATE2/AGENTS.md`, prompts, drafts, archived notes, and baseline processing reports.
- Duplicate Flutter projects such as `careconnect_calm_samples_v3`, `v4`, or `v5`.
- The full `feature/new-designs` tree or a wholesale v5 copy; selected design ideas must be ported into current `main` without deleting the merged foundation.
- `.dart_tool/`, `build/`, `coverage/`, IDE caches, local properties, transient cache lock files, or secrets. Continue tracking intentional dependency manifests and dependency lockfiles such as `pubspec.lock` and `package-lock.json`.
- Unverified claims, real patient/caregiver information, and submission-only packaging.

## Needs team or instructor confirmation

- Whether instructor handouts may be redistributed in the repository.
- Which screenshots and design exports belong in source control versus the course submission package.
- The final Week 4 screen set if the proposed eight-screen workflow is changed.
- Whether a generated HTML coverage report should be committed; the default is to report the percentage and keep generated coverage local.
